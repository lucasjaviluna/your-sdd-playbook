# Roadmap de aprendizaje SDD

## Introducción

Este playbook está diseñado como un camino progresivo para aprender y aplicar Specification-Driven Development en un entorno profesional.

El objetivo no es solamente comprender conceptos, sino desarrollar la capacidad de aplicar SDD en proyectos reales utilizando herramientas modernas:

* Azure DevOps.
* OpenSpec.
* GitHub.
* Claude Code.
* GitHub Copilot.

El aprendizaje está organizado desde los fundamentos hasta una adopción empresarial.

# Módulo 0 - Getting Started

## Objetivo

Construir la base conceptual necesaria para comenzar.

Aprenderás:

* qué es SDD;
* por qué surge;
* cómo cambia el ciclo de desarrollo;
* conceptos fundamentales;
* estructura del repositorio;
* flujo general.

Resultado esperado:

Puedes explicar SDD a otro desarrollador en pocos minutos.

---

# Módulo 1 - Fundamentos de SDD

## Objetivo

Comprender profundamente la filosofía detrás del enfoque.

Temas:

* Problemas del desarrollo tradicional.
* Specification como fuente de verdad.
* Diferencia entre User Story y Specification.
* Relación entre negocio, arquitectura y código.
* Beneficios y limitaciones.

Ejercicio:

Tomar una User Story simple y transformarla en una Specification básica.

Resultado esperado:

Aprender a pensar en términos de especificaciones.

---

# Módulo 2 - OpenSpec

## Objetivo

Aprender cómo estructurar y gestionar Specifications.

Temas:

* Qué es OpenSpec.
* Estructura de archivos.
* Ciclo de vida de una Specification.
* Versionado.
* Integración con Git.
* Integración con agentes IA.

Ejercicio:

Crear la primera Specification completa del proyecto Customer Portal.

Resultado esperado:

Tener una funcionalidad documentada lista para implementación.

---

# Módulo 3 - Requirements Engineering

## Objetivo

Aprender a transformar necesidades ambiguas en requerimientos claros.

Temas:

* Contexto.
* Alcance.
* Functional Requirements.
* Non Functional Requirements.
* Acceptance Criteria.
* Edge Cases.
* Business Rules.

Ejercicio:

Analizar una User Story real y descubrir requisitos ocultos.

Resultado esperado:

Crear Specifications claras y verificables.

---

# Módulo 4 - Diseño basado en Specifications

## Objetivo

Aprender a diseñar soluciones antes de programar.

Temas:

* Diseño frontend.
* Diseño backend.
* Contratos API.
* Modelos de datos.
* Diagramas.
* ADRs.
* Trade-offs técnicos.

Ejercicio:

Diseñar la arquitectura de una nueva funcionalidad del Customer Portal.

Resultado esperado:

Poder entregar una solución diseñada antes de escribir código.

---

# Módulo 5 - Desarrollo asistido por IA

## Objetivo

Aprender a trabajar con agentes de IA como parte del equipo.

Temas:

* Claude Code.
* GitHub Copilot.
* Prompt Engineering.
* Context Engineering.
* Generación de código.
* Refactoring.
* Revisión humana.

Ejercicio:

Implementar una funcionalidad completa utilizando una Specification.

Resultado esperado:

Utilizar IA como acelerador manteniendo control técnico.

---

# Módulo 6 - Testing basado en Specifications

## Objetivo

Conectar requisitos, implementación y validación.

Temas:

* Test Plan.
* Unit Testing.
* Integration Testing.
* End-to-End Testing.
* Generación de tests mediante IA.
* Trazabilidad.

Ejercicio:

Crear una estrategia de pruebas desde los Requirements.

Resultado esperado:

Que cada requisito tenga una validación asociada.

---

# Módulo 7 - Automatización y agentes

## Objetivo

Pasar de usar IA como asistente a utilizarla como parte del flujo operativo.

Temas:

* Agentes especializados.
* Orquestación.
* Automatización de tareas.
* CI/CD con SDD.
* Generación automática de documentación.
* Validaciones automáticas.

Ejercicio:

Crear un flujo donde un agente analice una Specification y genere tareas.

Resultado esperado:

Comprender cómo construir equipos híbridos humano + IA.

---

# Módulo 8 - Adopción empresarial

## Objetivo

Aprender cómo introducir SDD en una organización real.

Temas:

* Estrategia de adopción.
* Cambio cultural.
* Gobernanza.
* Métricas.
* Seguridad.
* Gestión del conocimiento.
* Escalabilidad.

Ejercicio:

Diseñar un plan de adopción para un equipo real.

Resultado esperado:

Poder liderar una iniciativa de SDD.

---

# Proyecto transversal: Customer Portal

Durante todo el aprendizaje construiremos un mismo proyecto.

## Funcionalidades

Ejemplos:

```text
Customer Portal

├── Login
├── Profile
├── Update Address
├── Benefits
├── Invoices
└── Payment Methods
```

Cada funcionalidad tendrá:

* Specification.
* Requirements.
* Design.
* Tasks.
* Tests.
* Implementación.

# Mensaje final

Specification-Driven Development no busca reemplazar el desarrollo tradicional.

Busca evolucionarlo.

La combinación de:

* buenas especificaciones;
* experiencia humana;
* herramientas de IA;
* procesos claros;

permite construir software de mayor calidad, con mayor velocidad y mejor trazabilidad.

El objetivo final no es escribir más código.

Es construir mejores sistemas.
